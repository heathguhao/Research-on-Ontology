# 第三篇《本体论下的自演进自学习组织体如何成为可能》修改方案

## ISSUE I3-01：把单一“组织体”改为多层复合治理主体（不采纳）

- **优先级**：P0
- **类型**：组织治理
- **评审状态**：不采纳，关闭，未执行。
- **原建议**：把公司拆成决策层、经营层、职能体系、二级单位、工厂和项目等多个主体，再分别讨论各自的权力与责任。
- **不采纳理由**：第三篇讨论的主体就是作为整体的“公司”，而不是公司内部的角色清单。组织当然包含许多部门和个人，但本篇关心的是公司能否形成统一认识、保存组织记忆，并以整体身份学习和演进。把主旨拆成权限、角色和分工，会缩小问题的格局，也会遮蔽“公司作为一个组织体”这一核心命题。
- **关闭边界**：保留单一组织体的叙述。正文不增加角色—权限—责任表，不把公司内部的分工结构升级为多个并列的本体主体。

## ISSUE I3-02：划清自动演进与企业治理的合法边界

- **优先级**：P1
- **类型**：组织治理
- **评审状态**：限定范围通过，未执行；实施须另行取得明确授权。
- **问题**：自演进不等于系统可以脱离公司的意志自行决定方向。机器可以发现变化、形成候选意见并帮助检查，但涉及公司核心认识的改变，仍然要由管理层作出判断。
- **修改动作**：只用一小段说明这条边界：技术系统负责提出和验证候选变化，管理层决定公司是否接受这些变化。无需展开权限模型、角色分工、批准层级或法律程序；权限不是本篇重点，因为本体本来就是服务于企业管理层形成和贯彻统一认识的工具。
- **建议落点**：变更闭环、风险分级、发布与回退章节。
- **验收标准**：读者能够看懂“系统可以帮助公司学习，但不能代替公司决定自己要成为什么”；正文不扩写为权限治理专题。

## ISSUE I3-03：增加多层本体与双向演进机制（不采纳）

- **优先级**：P1
- **类型**：战略引导
- **评审状态**：不采纳，关闭，未执行。
- **原建议**：建立集团、专业领域、二级单位、工厂或项目等多层本体，并让各层之间双向调整。
- **不采纳理由**：一个组织体只能有一个本体。企业本体表达的是公司对自身及其业务世界最核心的统一认识，必须集中确立，不能按组织层级分割，更不能让各层各自形成一套本体后再长期协商。多层本体会把组织重新带回语义割裂，与本篇追求的统一认识相冲突。
- **立场说明**：不同部门、现场和项目可以拥有不同数据、实例和工作情况，也可以为统一本体的修订提供材料，但这些差异不构成彼此独立的本体。材料可以来自各处，本体只能归于公司整体，并由管理层集中确认。
- **关闭边界**：不增加多层本体、双向演进、偏离声明和分层自治机制。后续所有相关 issue 均应服从“一家公司、一个本体”的原则，是否修改仍逐项评审。

## ISSUE I3-04：区分不同变化周期和版本程序（不采纳）

- **优先级**：P1
- **类型**：工程边界
- **评审状态**：不采纳，关闭，未执行。
- **原建议**：把数据、规则、标准、制度和战略分别纳入不同的变化周期与版本程序。
- **不采纳理由**：这条建议把日常业务变化和企业本体混在了一起。运行数据、具体流程和局部规则可以频繁变化，但本体只表达公司最核心、相对不变的认识，不负责容纳业务中的每个细节。因此，没有必要为本体建立一套覆盖各种业务速度的复杂版本制度。
- **关闭边界**：坚持统一本体和克制建模。正文可以承认本体在必要时会被修订，但不增加按秒、按月、按年分层的周期表、批准级别表或多套版本程序。

## ISSUE I3-05：区分三类“学习”

- **优先级**：P2
- **类型**：逻辑边界
- **评审状态**：限定范围通过，未执行；实施须另行取得明确授权。
- **问题**：“学习”有时指模型参数发生变化，有时指规则或本体被修订，有时又指公司改变了稳定的认识和行动方式。三者不是一回事，但这不是本篇需要展开的重点。
- **修改动作**：用几句话简单区分三种含义：模型学到模式，符号系统修订表达，公司形成并保持新的共同认识。说明模型更新不等于本体演进，本体改变也不等于公司已经真正改变。不要为三类学习分别建立复杂的输入、验证、风险和失败流程。
- **建议落点**：大语言模型能力边界、持续学习、双环学习段。
- **验收标准**：读者不会把三种学习混为一谈即可；相关内容保持简短，不打断“公司作为一个组织体自我学习和演进”的主线。
