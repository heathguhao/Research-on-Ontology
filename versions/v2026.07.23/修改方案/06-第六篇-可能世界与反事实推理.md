# 第六篇《可能世界与反事实推理》修改方案

## ISSUE I6-01：用贯穿案例证明场景分析价值（不采纳）

- **优先级**：P1
- **类型**：证据验证
- **评审状态**：不采纳，关闭，未执行。
- **原建议**：增加一个贯穿性的真实业务案例，并用指标证明场景分析相对规则引擎、脚本或仿真的新增价值。
- **不采纳理由**：目前没有这样的案例，也不要求第六篇承担实证证明。文章的任务是通过可能世界和反事实逻辑说明一种思考方式，而不是用单一工业案例证明业务效果。
- **关闭边界**：不补贯穿案例，不制作基线或指标，不暗示存在不可公开的案例结果。现有示例只承担帮助读者理解逻辑的作用，不把示意性例子包装成实践证据。

## ISSUE I6-02：区分反事实语义、因果模型与物理仿真（不采纳）

- **优先级**：P1
- **类型**：逻辑边界
- **评审状态**：不采纳，关闭，未执行。
- **原建议**：把反事实语义、结构因果模型和物理仿真分成三种模式，分别规定输入、验证方式和适用范围。
- **不采纳理由**：这会把一篇通过逻辑展开说理的文章，改造成因果建模和工程仿真的解决方案说明。第六篇并未声称已经解决现实中的因果识别或物理预测，也没有必要建立复杂的模式划分。可能世界和反事实推理在这里首先是帮助企业改变前提、观察逻辑后果的一种思想工具。
- **立场说明**：文章可以坦率承认逻辑推演不等于物理世界一定如此，但只需一句话说清边界，不展开因果模型、仿真模型和历史重建的技术分类，更不暗示本体论已经替代这些专业方法。
- **关闭边界**：不增加三分表或模式分配机制。后续若发现正文把逻辑后果说成已经解决现实因果或物理预测，应当弱化或删除过强表述，而不是补造一套不存在的解决方案。

## ISSUE I6-03：在场景进入行动前加入组织授权（不采纳）

- **优先级**：P1
- **类型**：组织治理
- **评审状态**：不采纳，关闭，未执行。
- **原建议**：为场景分析增加提出者、负责人、裁决者、行动批准者和复核者，并规定不同授权和回退程序。
- **不采纳理由**：权限问题不是第六篇的主旨。本系列面向企业管理层讨论公司如何形成统一认识，不需要在每一种思想工具之后附加角色和授权清单。引入这些内容会让反事实推理的哲学与逻辑主线失焦。
- **关闭边界**：不增加角色、权限、责任链或分类授权流程。场景推演是否进入现实行动属于企业既有管理行为，不在本篇展开。
