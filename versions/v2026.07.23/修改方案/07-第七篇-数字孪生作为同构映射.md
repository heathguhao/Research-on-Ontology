# 第七篇《数字孪生作为局部同构映射》修改方案

## ISSUE I7-01：将一般双射改为带上下文的身份对应（原替代方案不采纳）

- **优先级**：P0
- **类型**：逻辑边界
- **评审状态**：原替代方案不采纳；仅同意检查和弱化过于绝对的措辞，未执行；实施须另行取得明确授权。
- **原建议**：用带时间、上下文、角色和置信状态的身份对应关系取代双射，并进一步引入一对多、多对一和待决状态。
- **不采纳理由**：这套替代论断本身写得过大，边界也没有得到充分说明。它不是对原文的简单纠偏，而是在缺少依据的情况下另建一套更复杂的数字身份理论，因此不能用它取代原文。
- **修改动作**：保留局部双射作为第七篇的基本思路。实施时只检查“所有对象必然如此”“双射适用于任何数字孪生”等过于绝对的句子；确有必要时，改成“在本文讨论的局部范围和既定颗粒度内”等较稳妥的说法。不得借弱化措辞之机加入多身份、上下文状态或多重映射的新框架。
- **建议落点**：摘要、第 1 节公式、第 3 节局部实体双射、结论。
- **验收标准**：原文的核心论断仍是“实例数据在局部颗粒度上追求双射”；仅删除无法负责的全称语气，不把尚未明确的替代理论写进正文。

## ISSUE I7-02：增加制造生命周期和多视角身份（不采纳）

- **优先级**：P1
- **类型**：工程边界
- **评审状态**：不采纳，关闭，未执行。
- **原建议**：补充设计、建成、运行和维护等制造生命周期状态，并增加同一对象在多个系统中的不同身份与视角。
- **不采纳理由**：这项建议进入了过细的制造业务设计，却没有可用案例支撑。它会迫使文章作出关于生命周期、系统身份和对齐方式的具体论断，而这些论断目前既武断，也不是第七篇成立所必需的内容。
- **关闭边界**：不增加生命周期表、多系统身份表或相关案例，不修改现有论述来迁就这一套细分框架。

## ISSUE I7-03：把规则相容与物理反馈绑定

- **优先级**：P1
- **类型**：证据验证
- **评审状态**：限定范围通过，未执行；实施须另行取得明确授权。
- **问题**：业务规则与数字实现之间相容，只能说明符号表达前后一致；它本身不能保证现实中的对象一定按照数字规则产生预期结果。数字孪生要保持与业务世界的联系，仍需接受物理反馈。
- **修改动作**：只用一小段说明：规则相容负责保证数字世界没有背离企业已经确立的业务逻辑，物理反馈负责检验数字世界是否仍与现实对象相符。两者结合，才能使“同构映射”不仅停留在符号内部。不展开规则分类、数据窗口、误差带、仿真方案或指标体系。
- **建议落点**：第 4 节交换关系、第 5 节验收条件。
- **验收标准**：正文简明说清规则相容与物理反馈各自解决什么问题，并说明只有符号上的相容还不够；相关内容不能扩张成完整的验收方案。

## ISSUE I7-04：将数字孪生嵌入企业多层语义治理（不采纳）

- **优先级**：P1
- **类型**：战略引导
- **评审状态**：不采纳，关闭，未执行。
- **原建议**：让集团、专业领域、二级单位和现场分别拥有不同的语义定义与扩展权，再通过多层治理进行对齐。
- **不采纳理由**：本体论必须集权。一个组织体只能拥有一个统一本体，本体中所有定义的权力属于组织体内的主权者，不能按集团层级、专业领域或现场分散。所谓多层语义治理会把统一认识重新拆成多个局部认识，再把长期协调分歧误当成治理能力。
- **立场说明**：专业部门、二级单位和现场可以提供事实、实例和修订材料，但不能各自取得本体定义权。组织体内的主权者吸收这些材料并形成统一定义，数字孪生据此保持统一的身份、规则和解释框架。
- **关闭边界**：不增加专业扩展、单位本体、现场语义自治或多层定义权。后续所有涉及企业语义治理的建议，都必须服从“一家公司、一个本体、定义权归于组织体内主权者”的原则，是否修改仍逐项评审。
