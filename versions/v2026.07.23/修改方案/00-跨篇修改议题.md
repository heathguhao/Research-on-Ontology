# 跨篇修改议题

## ISSUE IC-01：明确哲学论证与工程判断的责任边界

- **优先级**：P0
- **类型**：逻辑边界
- **评审状态**：按委托人意见修订，待确认，未执行。
- **问题**：本系列以哲学为实质性的论述主线。需要处理的不是哲学内容过多，而是哲学论证、形式定义、工程判断和实证结论偶有责任混同，使读者可能把概念框架误读为工程正确性证明，或反过来把哲学仅仅理解为修辞和装饰。
- **修改动作**：保留并强化哲学对概念框架、观察方式和规范方向的论证作用，同时区分不同陈述的责任：形式定义交代所采用的语法、语义或推理条件；哲学论证充分说明概念来源、问题意识和规范含义；工程原则说明适用对象、条件与边界；涉及比较优势、性能或实际效果的结论，仅在具有可公开证据时作出。全书统一检查命题框、公式前后的因果词以及“必然、唯一、证明”等强词，但不把哲学论证降格为不承担实质内容的“类比标签”。
- **证据边界**：现阶段不要求通过补充实验来完成本 issue。正文不把缺少公开实验写成缺陷，不虚构实验、数据或结果，也不明示或暗示存在不可公开的实验。没有公开证据时，只收敛实证性结论，不削弱哲学主线。
- **建议落点**：八篇全文及合订本编辑说明；须在本 issue 获得进一步执行授权后再实施。
- **验收标准**：哲学仍是贯穿系列的实质性论述；哲学命题与工程结论的责任边界清楚；没有公开证据支撑的比较优势或实证结论被收敛；全文既不虚构实验，也不以“尚无实验”为由删除哲学论证。

## ISSUE IC-02：用一个有限制造场景贯穿八篇（不采纳）

- **优先级**：P1
- **类型**：证据验证
- **评审状态**：不采纳，关闭，未执行。
- **原建议**：以一个有限制造场景贯穿八篇，并要求共同案例具备统一数据、错误类型、治理成本和业务结果。
- **不采纳理由**：八篇各自承担独立的论述任务，不以同一制造案例作为共同结构，也不把统一数据、共同指标或案例连续性设为全书成立的条件。
- **关闭边界**：删除后续执行顺序对本 issue 的依赖。本次关闭不自动修改 `I4-03`、`I6-01`、`I8-03`，三个分篇 issue 留待逐篇评审。

## ISSUE IC-03：拆分三种发布版本

- **优先级**：P1
- **类型**：战略引导
- **评审状态**：评审通过，未执行；实施须另行取得明确授权。
- **问题**：同一合订本很难同时承担学术讨论、工程实施和央企战略引导。强行兼顾会使理论过重、工程证据过轻、领导者关心的组织命题不够集中。
- **修改动作**：保留研究版作为来源母本；从中提炼工程白皮书版，突出架构、接口、案例、指标和实施制度；另形成央企战略版，围绕认知主权、组织记忆、多级治理、自主可控、产业控制力和行动责任展开。战略版引用研究版结论，但不堆叠公式和学术争论。
- **建议落点**：全书版本规划，不直接改写某一篇的独立性。
- **验收标准**：三种版本分别有明确读者、篇幅、证据要求和术语密度；战略引导来自治理机制和案例，不来自口号化段落。

## ISSUE IC-04：公开文章与受控技术材料分离

- **优先级**：P1
- **类型**：权利保护
- **评审状态**：限定范围通过，未执行；实施须另行取得明确授权。
- **问题**：公开文章用于表达思想框架，Proto 则包含更具体的结构设计和技术实现信息，两者不应采用相同的公开范围。
- **修改动作**：公开文章与受控技术材料分离。任何 Proto 源文件（包括 `ontology.proto`）均不进入公开 GitHub 仓库、公开合订本或普通分发材料；公开文本如需涉及 Proto，只保留论证所必需且已经获准公开的概念说明，不附源文件或可还原实现的完整细节。
- **暂缓事项**：副本编号、接收人台账、作品登记、专利筛查、商业秘密制度及其他分发控制措施暂不考虑，也不因本 issue 的限定通过而获得实施授权。
- **建议落点**：后续公开仓库和出版物的文件范围检查。
- **验收标准**：公开仓库、公开合订本和普通分发材料均不包含 Proto 源文件；本 issue 不被解释为已经批准其他权利保护措施。
